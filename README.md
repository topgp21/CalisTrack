# CalisTrack — הכוח להתמיד

PWA אישית בעברית, RTL, ללא ספריות לקוח או תהליך build. תיקיית `public` היא האתר; `server` הוא שרת Google Apps Script. כל הקבצים שייכים לפרויקט חדש זה בלבד.

**מצב הפריסה המעודכן — 17.10.2026:** האתר פעיל ב־https://topgp21.github.io/CalisTrack/ . שרת Apps Script נפרס, כניסת Google הושלמה בטלפון, ושמירת אימונים אמיתית ב־Google Sheets אומתה בקריאה עצמאית דרך חיבור Drive. 27 בדיקות אוטומטיות עברו. אימות הענן מצא אימון בדיקה יחיד עם שלוש גרסאות: שמירה של 6 חזרות בסט אחד בלבד, תיקון ל־7, ומחיקה לוגית. טבלת הסטים שמרה במדויק ארבעה סטים שלא בוצעו. הגישה האנונימית לקריאה ולכתיבה נבדקה ונחסמה. הבדיקה בדפדפן אימתה גם קריאה חוזרת, ניסיון חוזר ללא כפילות ודחיית גרסה ישנה. לא בוצעה התקנת PWA או בדיקת מצב טיסה פיזית על המכשיר. הפרויקט נשאר ב־Spark ללא חיבור חיוב שנעשה על ידינו; לא הופעל שירות בתשלום. אין ליצור גיליון, סקריפט או פרויקט OAuth חדשים עבור הפריסה הקיימת.

## פתיחה מקומית

נדרשים Python 3 ו־Node 20 ומעלה לבדיקות בלבד. אין התקנת תלויות.

```sh
cd /workspace/calistrack
npm test
npm run serve
```

פתח במחשב `http://localhost:8080`. אין לפתוח `index.html` ישירות כקובץ. ניתן להשתמש באימון, בהיסטוריה, במדידות ובגיבוי ללא חיבור Google. בשרת פיתוח זה `localhost` מתאים ל־Service Worker; כתובת HTTP של מחשב ברשת הביתית אינה מתאימה להתקנת PWA בטלפון. לטלפון יש לפרוס ב־HTTPS.

## ארכיטקטורה ושמירה

- `public/core.js`: תוכנית, מזהים, בדיקות תקינות, סטטיסטיקה, מיזוג ו־CSV.
- `public/store.js`: IndexedDB. מצב, טיוטה ותור פעולות נשמרים יחד בטרנזקציה אחת; כשל נמסר למשתמש.
- `public/app.js`: מסכים, כניסת Google, תור סנכרון, טיפול בהתנגשות וגיבויים.
- `public/sw.js`: מטמון מעטפת; אין שמירת תשובות Google או אסימוני כניסה במטמון.
- `server/Code.gs`: אימות, נעילה, בקרת גרסאות ויומן append-only.

כל אימון וכל סט מקבלים UUID. אימון נוצר כטיוטה בזמן התחלה; לחיצה על סיום מקבעת תאריך סיום ומשאירה סטים שלא בוצעו כ־`done:false`. רק אימונים שמורים עם לפחות סט אחד שבוצע נספרים ביעד. שני אימונים בשבוע או יותר מזכים בשבוע רצף; השבוע הנוכחי יכול עדיין להיות בתהליך. השבוע מתחיל ביום שני לפי השעון המקומי של הטלפון. תוכנית שבוע 3 מחושבת לפי הזמן שחלף מהאימון המוקדם בהיסטוריה הזמינה, ולא מספר האימונים. התאמה ידנית לסטים גוברת על ברירת המחדל.

בתור: `opId`, `baseRevision` ועותק מלא של הרשומה. ניסיון חוזר באותו מזהה מחזיר אותה תוצאה. עדכון מותנה בגרסה כדי למנוע דריסה ממכשיר אחר. סטים נשמרים בתוך תמונת אימון אחת ולכן אין commit של חצי אימון. הסנכרון שולח את התור ואז מושך את המצב העדכני; רשומה עם שינוי מקומי ממתין אינה נדרסת במשיכה. עם חזרת האינטרנט מתבצע ניסיון סנכרון אם הכניסה עדיין קיימת; גם ניסיון חוזר כל דקה לפעולות ממתינות. אסימון שפג מחייב כניסה מחדש.

`Operations` הוא מקור האמת בענן. פעולת כתיבה אחת נרשמת קודם ליומן, ורק אחר כך מוקרנת לטבלאות `Workouts`, `Sets`, `Exercises`, `Measurements`. כשל לאחר כתיבת היומן אינו מכפיל פעולה; ניסיון חוזר בונה את הטבלאות מחדש. מחיקות הן סימון `deleted`, והיומן שומר גם גרסאות קודמות. אין לערוך את הטבלאות הנגזרות ידנית: סנכרון הבא בונה אותן מחדש. אין למחוק או לערוך את `Operations`. Google Sheets אינו מסד נתונים עם טרנזקציות מרובות טבלאות; היומן והנעילה נועדו לפצות על כך, ובדיקת הכשל לאחר commit כלולה בבדיקות.

התנגשות עוצרת את התור ומוצגת בהגדרות עם שתי הגרסאות. ניתן לבחור במפורש גרסת מכשיר או ענן; לפני כן יורד גיבוי מלא. הורדת קובץ עדיין תלויה באישור ובתקינות הדפדפן, ולכן יש לוודא שהקובץ קיים. גרסאות שנשלחו בעבר נשארות ביומן. חלון נוסף באותו דפדפן נחסם באמצעות Web Locks ב־Chrome כדי למנוע שני כותבים מקומיים.

- עדכוני האתר דרך main נבדקים ומתפרסמים אוטומטית ב־GitHub Pages. סקריפט בדיקת HTTPS משווה את הקבצים שפורסמו למקור ובודק שהשרת דוחה קריאה וכתיבה ללא כניסה.

## הוראות פריסה חדשה — לא להריץ מחדש על הפריסה הקיימת

### 1. פריסת האתר ב־HTTPS

העלה **רק את תוכן `public/`** לאחסון סטטי כגון Cloudflare Pages, GitHub Pages או אחסון HTTPS שברשותך. אין צורך בפקודת build. תיקיית הפלט היא `public`; `index.html` חייב להיות בשורש הפרסום. שמור כתובת קבועה: החלפת origin יוצרת אחסון מקומי חדש. יש לגבות לפני מעבר כתובת. אין להעלות גיבויים או נתוני אימונים לאחסון האתר.

אם משתמשים ב־GitHub Pages: צור מאגר חדש המיועד רק ל־CalisTrack, העלה את תוכן public לענף ייעודי, Settings → Pages → Deploy from a branch, בחר את הענף ואת `/ (root)`. ודא ש־HTTPS נאכף. אפשר לפרוס תחת נתיב משנה; הקישורים יחסיים.

### 2. Google Sheets פרטי

1. באותו חשבון Google שישמש לאימונים, צור גיליון חדש בשם `CalisTrack`.
2. שיתוף: Restricted. אין לשתף Anyone with the link ואין להפעיל Publish to web.
3. העתק את מזהה הגיליון מהכתובת בין `/d/` לבין `/edit`.
4. Extensions → Apps Script. זהו פרויקט חדש המחובר רק לגיליון החדש.
5. החלף את `Code.gs` בתוכן `server/Code.gs`.
6. Project Settings → Show appsscript.json manifest file. החלף את המניפסט בתוכן `server/appsscript.json`.

### 3. OAuth לחשבון יחיד

1. צור פרויקט חדש דרך Firebase Console במסלול Spark, ללא חיבור חשבון חיוב. זה יוצר גם פרויקט Google Cloud שאפשר לבחור בו ב־Google Auth Platform. המסך הרגיל ליצירת פרויקט ב־Cloud Console עשוי לחייב בחירת חשבון חיוב; אין להשתמש בו כאשר נדרש מסלול ללא Billing. אין לשנות פרויקט קיים.
2. Google Auth Platform → Branding: הגדר שם CalisTrack וכתובות התמיכה שלך. Audience: אם זה Gmail אישי בחר External; בזמן Testing הוסף רק את חשבונך כ־Test user. אין צורך בהרשאת Sheets אצל המשתמש בדפדפן: הלקוח מבקש רק כניסת Google בסיסית.
3. Clients → Create client → Web application.
4. ב־Authorized JavaScript origins הוסף את ה־origin המדויק של האתר, למשל `https://your-name.github.io` (ללא הנתיב `/calistrack`). לפיתוח אפשר להוסיף `http://localhost:8080`.
5. אין צורך ב־redirect URI לזרימת GIS popup callback שבה משתמש האתר. אין להוסיף client secret לקוד או להגדרות הלקוח.
6. העתק את Client ID שמסתיים ב־`.apps.googleusercontent.com`.
7. אם Chrome מציג שגיאת origin או חשבון בדיקה, בדוק התאמה מדויקת של origin ו־Test users. שינוי הגדרות OAuth יכול לקחת זמן להתעדכן.

### 4. הגדרות שרת ופריסת Apps Script

Project Settings → Script Properties → Add script property:

| מפתח | ערך |
|---|---|
| `SPREADSHEET_ID` | מזהה הגיליון החדש |
| `GOOGLE_CLIENT_ID` | ה־Client ID מסעיף OAuth |
| `OWNER_EMAIL` | כתובת Google המדויקת של המשתמש היחיד |

Deploy → New deployment → Web app:

- Execute as: **Me**, בעל הגיליון.
- Who has access: **Anyone** לצורך תעבורת HTTP חוצת מקורות, ואז Deploy ואשר את הרשאות Sheets ו־external requests לחשבונך.
- העתק כתובת `/exec`, לא `/dev` ולא כתובת העורך.

**הבחנה חשובה:** כתובת HTTP נגישה לציבור, אך אינה מאפשרת שום קריאה או כתיבה אנונימית. כל POST נבדק מול Google tokeninfo וכולל בדיקת audience, issuer, expiration, email_verified וכתובת המשתמש המותר. GET אינו חושף נתונים. נעילה וכתיבה מתרחשות רק לאחר אימות. אין סוד משותף בדפדפן. אם מדיניות Workspace אינה מאפשרת פריסה נגישה ל־Anyone, הארכיטקטורה הזו אינה מתאימה לחשבון זה ללא שרת מתווך מאומת; אין לבטל אימות כדי לעקוף את ההגבלה.

הפריסה משתמשת בתגובת ContentService המופנית ל־`script.googleusercontent.com`. הלקוח שולח `text/plain` כדי להימנע מבקשת preflight שאינה נתמכת ב־Apps Script. קבלה של redirect וקריאת התגובה חייבות להיבדק בדפדפן בפועל; חסימת ארגון, דפדפן או רשת עשויה למנוע זאת. אין להשתמש ב־`no-cors`: הוא יסתיר את אישור השמירה.

עדכון שרת בעתיד: Deploy → Manage deployments → Edit → New version → Deploy. שמור אותה כתובת `/exec`.

### 5. חיבור באפליקציה

הגדרות → חיבור Google Sheets → הדבק כתובת `/exec` ו־Client ID → שמור חיבור. לחץ על כפתור הכניסה של Google ובחר רק את החשבון המותר. Client ID הוא מזהה ציבורי ולא מפתח. אסימון הכניסה נשאר בזיכרון ונשלח ב־HTTPS; אינו נשמר ב־IndexedDB, ב־localStorage או בקובץ גיבוי. אין לבצע רישום של גופי בקשות בצד השרת.

לאחר סנכרון ראשון אמורות להיווצר לשוניות `Operations`, `Workouts`, `Sets`, `Exercises`, `Measurements`. הלשונית הריקה המקורית יכולה להישאר.

## בדיקת קבלה לפני הסתמכות על הענן

1. שמור אימון בדיקה עם סט אחד בלבד. ודא בהיסטוריה שרק הסט הזה מסומן.
2. התחבר וסנכרן. ודא הודעת הצלחה, תור ריק, שורת אימון אחת ב־Workouts ו־done נכון ב־Sets. ודא id תואם לפרטי האימון.
3. במצב טיסה: התחל אימון, הזן נתון, סמן סט וסיים. סגור ופתח את האפליקציה כשהיא לא מקוונת. ודא שהרשומה קיימת והתור אינו ריק.
4. חזור לרשת והיכנס מחדש אם צריך. סנכרן פעמיים. ודא שאותו id מופיע פעם אחת בלבד בטבלאות הנגזרות.
5. תקן סט וסנכרן. ודא revision עולה, אין סט נוסף, והגרסה הישנה נשארת ב־Operations.
6. ממכשיר/דפדפן שני משוך את אותו אימון. שנה אותו בשני המכשירים בלי לסנכרן, סנכרן אחד ואז את האחר. ודא שהאחר מציג התנגשות ולא דורס. בדוק בחירה מפורשת בהגדרות.
7. מחק אימון בדיקה עם אישור. ודא שהוא הוסתר באפליקציה, ושהיומן נשאר ו־deleted אמת בטבלאות. בדוק גם משיכה במכשיר שני.
8. הורד JSON ו־CSV. שמור JSON מחוץ לטלפון. בכתובת/פרופיל בדיקה נקיים שחזר את JSON וודא שתוצאות הסטים והמדידות נשמרו. שחזור משמר רשומות קיימות ומוסיף חסרות; אסור לראות בו דריסה מלאה של מסד קיים.
9. נסה כניסה עם חשבון אחר; שרת חייב להחזיר חשבון לא מורשה. POST ללא token חייב להיכשל. בדוק שלא מופיעים נתונים בתגובה אנונימית.
10. רק לאחר כל אלה אפשר לומר שהענן חובר ואומת.

## גיבוי, שחזור ותחזוקה לשנים

- הורד גיבוי מלא מההגדרות באופן קבוע, ולפני החלפת מכשיר, כתובת אתר או ניקוי נתוני דפדפן. CSV כולל סטים; JSON כולל גם מדידות, טיוטה ותור פעולות.
- שמור עותק של הגיליון מדי פעם ב־Drive דרך File → Make a copy. זהו גיבוי נפרד: מחיקת חשבון או גיליון אינה נפתרת על ידי סימון מחיקה באפליקציה.
- לאיפוס מחיקה שגויה: שחזר רשומה מגרסה מוקדמת בקובץ גיבוי בסביבת שחזור נפרדת, ואז סנכרן ובחר בגרסה המקומית בהתנגשות. אין למחוק שורות ביומן; לשחזור מתקדם יש לייצר פעולת תיקון חדשה על בסיס הגרסה האחרונה.
- אחסון דפדפן עלול להימחק על ידי מערכת ההפעלה או המשתמש. האפליקציה מבקשת אחסון persistent אך אינה יכולה להבטיח שהבקשה תאושר. נתונים מקומיים שטרם סונכרנו אינם גיבוי ענן.
- אין הצפנה נוספת למסד המקומי; השתמש בנעילת המכשיר. אל תשתף גיבויים המכילים מדדים אישיים.
- Apps Script ו־Sheets מוגבלים במכסות וזמן ריצה. למשטר של שני אימונים בשבוע זה פתרון פשוט; היומן כולו נקרא בכל סנכרון והטבלאות נבנות מחדש. אם מתחילות שגיאות זמן/מכסה, אין למחוק היסטוריה: הורד גיבוי ועבור לכתיבה מצטברת עם מיגרציה מתועדת.
- עדכון קובצי PWA: העלה מעטפת מלאה והחלף את מספר CACHE ב־sw.js. סגור את כל חלונות האפליקציה ופתח מחדש כדי להפעיל את העובד החדש. נתוני IndexedDB אינם חלק ממטמון המעטפת.

## בדיקות שבוצעו ומגבלות

27 בדיקות אוטומטיות: תוכנית שבועות, UUID, אימון חלקי ותיקון, ולידציה, ספירה ורצף, CSV, מיזוג ותור, אחסון/טעינה/כשל commit, שרת עם אימות/כפילויות/התנגשות/מחיקה, כשל הקרנה לאחר commit ונכסי PWA. בדיקות האחסון משתמשות בכפיל API אסינכרוני ובדיקות השרת בכפיל Sheets/Google; אלה אינן בדיקות אינטגרציה עם Google או IndexedDB אמיתי. נבדק גם תחביר JavaScript. הכניסה והבדיקה האוטומטית באפליקציה בוצעו בטלפון, כולל תעבורת CORS וכתיבה לגיליון אמיתי. אימות עצמאי אישר את היומן והטבלאות הנגזרות. בדיקות התקנה במסך הבית, אימון רגיל מלא ומצב טיסה פיזי עדיין לא בוצעו.

## פתיחה ב־Samsung Galaxy S25 Plus והוספה למסך הבית

1. לאחר פריסת HTTPS פתח ב־**Chrome** בטלפון את כתובת האתר הקבועה, לא כתובת Apps Script.
2. ודא שהעמוד נטען במלואו פעם אחת ברשת, בחר מצב כהה/בהיר והגדר את החיבור ל־Google כמתואר לעיל.
3. בתפריט ⋮ של Chrome בחר **הוספה למסך הבית** → **התקנת אפליקציה** אם האפשרות מופיעה. אשר את השם CalisTrack.
4. פתח מהסמל החדש. בדוק פתיחה במצב טיסה לאחר הטעינה הראשונה. אם מופיע רק קיצור דרך, בדוק HTTPS, מניפסט, אייקונים ו־Service Worker בכלי המפתחים לפני הסתמכות על מצב לא מקוון.
5. לחץ **התחל אימון**, חמם 3 דקות, הזן תוצאה בפועל ולחץ **בוצע** לכל סט בנפרד. סיים בשחרור 2 דקות ואז **סיים ושמור אימון**.
6. סנכרן ובדוק שהפעולות הממתינות התרוקנו. אין צורך בתזכורת נוספת: תזכורת ChatGPT הקיימת ב־21:30 נשארת כפי שהיא.


## כלי הפריסה המוכנים בענן

`.github/workflows/pages.yml` מריץ בדיקות ומפרסם את public ל־GitHub Pages לאחר push ל־main. יש להפעיל Pages באמצעות GitHub Actions במאגר החדש בלבד לאחר חיבור החשבון. אין תלויות או סודות הנדרשים לאירוח הסטטי.

`scripts/deploy-gas.mjs` מוכן ליצירת פרויקט Apps Script חדש המחובר לגיליון שנוצר, עדכון קוד, גרסה ופריסה. הוא מסרב לגעת בפרויקט שלא נוצר על ידו. נדרשים Secrets בזמן ריצה: CALISTRACK_GOOGLE_ACCESS_TOKEN עם הרשאות script.projects, script.deployments, ו־openid/email לצורך אימות זהות; ייתכן שנדרש drive לפי הרשאות הפרויקט. מזהה OAuth ציבורי CALISTRACK_GOOGLE_CLIENT_ID נדרש גם כן. אין להדביק אסימונים בשיחה, בקוד או ב־Git. הכלי אינו יוצר לקוח OAuth, אינו מעניק הסכמה לבעל הסקריפט ואינו מוכיח שהפריסה עובדת. פרטי routing שאינם סודיים נוצרים בקובץ DeploymentConfig בצד השרת; אסימוני גישה לא נכללים בו.

`scripts/integration.mjs` מוכן לבדיקה אמיתית לאחר הפריסה, עם CALISTRACK_GOOGLE_ID_TOKEN שמוזן כ־Secret זמני של החשבון המותר. הוא בודק כתיבת אימון חלקי, קריאה, ניסיון חוזר ללא כפילות, דחיית גרסה ישנה ודחיית קריאה/כתיבה ללא אימות; בסיום מסמן את אימון הבדיקה כמחוק. הבדיקה בפריסה הנוכחית בוצעה בפועל באמצעות public/diagnostics.js בטלפון, ותוצאות היומן נקראו ואומתו באופן עצמאי. אין צורך ליצור ID-token Secret עבור שימוש שוטף. כניסה מחשבון Google אחר לא נבדקה בדפדפן אמיתי; דחיית זהות אחרת מכוסה בבדיקות השרת האוטומטיות.

`public/deployment-config.js` מכיל רק כתובת שרת ומזהה OAuth ציבוריים. בעת פריסה מוצלחת הכלי ממלא אותם כדי לחסוך העתקה ידנית בטלפון.


## בדיקת ענן מתוך האפליקציה

`public/diagnostics.js` רץ לאחר הכניסה הראשונה, עם האסימון בזיכרון בלבד. הוא בודק חסימת גישה אנונימית, שמירה וקריאת אימון חלקי, ניסיון חוזר באותו מזהה פעולה, תיקון וטעינה חוזרת, דחיית עדכון ישן ומחיקה לוגית עם קריאה חוזרת. אימון הבדיקה מסומן `diagnostic:true` ואינו נספר באימונים או ב־CSV. היומן שומר את גרסאותיו גם לאחר הסימון כמחוק. במקרה של כשל רשת נשמר מזהה מקומי לניקוי מאוחר, ובדיקה חוזרת מטפלת בו לפני יצירת בדיקה נוספת. הניקוי מסרב למחוק אימון שאינו מסומן במפורש כרשומת בדיקה. אפשר להפעיל שוב דרך הגדרות → בדוק שמירה בענן.

לפתיחה יומית השתמש בכתובת האתר הקבועה או בסמל המותקן. אם מוצג שהאפליקציה כבר פתוחה, סגור את חלון CalisTrack האחר; אין לנקות נתוני דפדפן כדי לפתור זאת. אחרי התקנה ממסך Chrome, סגור את לשונית CalisTrack בדפדפן ופתח מהסמל כדי שלא יפעלו שני חלונות כותבים.
